# 文件“详细信息（含修改）”能力扩展设计

## 1. 目标
- 在现有“通用文件属性 + 改名”基础上，增加“按文件类型展示元数据”。
- 明确每个格式的字段：哪些只读、哪些可修改。
- 先做只读主干，后做可修改能力，降低风险。

## 2. 当前现状
- 入口菜单：上下文菜单项可打开详情弹窗。
- 已有可编辑：文件名（renameDocument）。
- 已有通用属性：路径、类型、大小、修改时间、DocumentProvider 基础列。
- 已有部分格式能力：
  - 音频标签读取（MediaMetadataRetriever，已有 title/artist/album 等读取代码）。
  - 压缩包一级目录浏览（ZIP/7z 的首层条目预览）。

## 3. UI 结构建议
- 顶部区：基础信息（现有）+ 改名（现有）。
- 分段区：按类型显示“元数据卡片”。
- 底部区：操作按钮（关闭；后续可加“保存修改”）。

建议的详情页分段：
- 基础信息
- 类型元数据
- 可修改字段（仅当该类型支持写入时显示）
- 调试/原始字段（可折叠）

## 4. 元数据能力矩阵（设计稿）

| 类型 | 目标格式 | 只读字段（首批） | 可修改字段（建议） | 实现建议 | 风险 |
|---|---|---|---|---|---|
| 通用文件 | 全部 | 名称、路径、MIME、大小、修改时间、文档ID | 文件名 | DocumentsContract + ContentResolver + renameDocument | 低 |
| 音频 | mp3,m4a,flac,ogg,wav | 标题、艺术家、专辑、专辑艺术家、流派、年份、时长、码率、采样率、位深、MIME | V2再做：标题/艺术家/专辑/流派/年份 | 读：MediaMetadataRetriever；写：后续引入专门 tag 库并走 SAF 临时文件回写 | 中-高 |
| 视频 | mp4,mkv,webm,mov | 时长、宽高、旋转、码率、容器MIME、音视频轨道 MIME/参数 | 暂不支持 | 读：MediaMetadataRetriever + MediaExtractor/MediaFormat | 中 |
| 图片 | jpg,jpeg,png,webp,heic | 宽高、拍摄时间、相机型号、镜头、ISO、曝光、GPS(可脱敏展示) | V2可做：方向、拍摄时间、作者、备注（限Exif支持格式） | 读/写：ExifInterface（需可写 FD） | 中 |
| PDF | pdf | 页数、标题、作者、主题、关键词、创建时间、修改时间、版本（尽可能） | 暂不支持（V3评估） | 页数：PdfRenderer；文档信息：引入 pdfbox-android 或等价库 | 中 |
| EPUB | epub | 书名、作者、语言、标识符、出版者、章节数 | 暂不支持（V3评估） | 读：复用现有 EPUB 解析结果；写：重打包成本高 | 高 |
| 压缩包 | zip,7z | 首层目录、条目数、加密状态 | 暂不支持 | 复用现有 ZipOperations 能力 | 低 |

## 5. 可修改能力边界（建议）
- V1（稳定优先）：只保留“改名”可修改，其余全部只读。
- V2（受控开放）：仅开放图片 Exif 的少量字段写入（可回退）。
- V3（重度能力）：音频标签写入、PDF/EPUB 元信息写入（需要额外库与回归测试）。

## 6. 首批支持格式建议
- 必做（V1）：
  - 通用文件（全类型）
  - 音频只读
  - 视频只读
  - 图片只读
  - PDF 只读（先页数，文档信息按库评估可降级）
- 暂缓（V2+）：
  - 图片 Exif 写入
  - 音频标签写入
  - EPUB/PDF 元信息写入

## 7. 数据模型建议
- 统一响应模型：
  - kind: 通用/音频/视频/图片/PDF/EPUB/压缩
  - readonlyFields: List<Pair<label, value>>
  - editableFields: List<EditableField>
  - warnings: List<String>
- 目的：UI 与采集逻辑解耦，后续扩展格式不改 UI 主体。

## 8. 实施分期建议
- P1（1个迭代）：
  - 详情页拆成“基础信息 + 类型卡片”。
  - 接入音频/视频/图片/PDF 只读提取。
  - 增加错误与权限提示（读取失败、格式不支持）。
- P2（1-2个迭代）：
  - 图片 Exif 可编辑（白名单字段）。
  - 变更预览与保存确认。
- P3（后续）：
  - 音频标签写入。
  - PDF/EPUB 元信息写入评估与实现。

## 9. 验收标准（V1）
- 用户在“详细信息（含修改）”中能看到：
  - 基础信息始终可见。
  - 识别到类型时显示对应元数据卡片。
  - 非支持类型给出“暂无类型元数据”。
- 改名行为保持现有逻辑不回归。
- 不增加崩溃，不阻塞主线程（元数据读取应在 IO 线程）。
